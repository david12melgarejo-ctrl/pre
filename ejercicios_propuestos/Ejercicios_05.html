Las 10 Heurísticas de Usabilidad de Jakob Nielsen

Principios generales para el diseño de interfaces de usuario explicados de forma sencilla.

  1. Visibilidad del estado del sistema

    El sistema siempre debe mantener informados a los usuarios de lo que está ocurriendo, a través de comentarios apropiados dentro de un tiempo razonable (por ejemplo, una barra de carga o un mensaje de "guardando").

  2. Relación entre el sistema y el mundo real

    El sistema debe hablar el idioma del usuario, con palabras, frases y conceptos que le sean familiares, en lugar de utilizar términos técnicos del sistema. Debe seguir las convenciones del mundo real.

  3. Control y libertad del usuario

    Los usuarios a menudo eligen funciones del sistema por error y necesitan una "salida de emergencia" claramente marcada para abandonar el estado no deseado sin tener que pasar por un diálogo extendido (como los botones "Deshacer" o "Cancelar").

  4. Consistencia y estándares

    Los usuarios no deberían tener que preguntarse si diferentes palabras, situaciones o acciones significan lo mismo. Sigue las convenciones de la plataforma (por ejemplo, que el carrito de compras siempre esté arriba a la derecha).

  5. Prevención de errores

    Mucho mejor que un buen mensaje de error es un diseño cuidadoso que evite que ocurra el problema en primer lugar. Por ejemplo, desactivar un botón de envío hasta que el formulario esté completamente lleno.

  6. Reconocer antes que recordar

    Minimiza la carga de memoria del usuario haciendo visibles los objetos, las acciones y las opciones. El usuario no debería tener que recordar información de una parte del proceso a otra.

  7. Flexibilidad y eficiencia de uso

    Los aceleradores (como los atajos de teclado o comandos rápidos), ocultos para el usuario novato, pueden acelerar la interacción para el usuario experto, permitiendo que el sistema se adapte a ambos tipos de público.

  8. Estética y diseño minimalista

    Las interfaces no deben contener información que sea irrelevante o que rara vez se necesite. Cada unidad adicional de información en una interfaz compite con las unidades de información relevantes y disminuye su visibilidad relativa.

  9. Ayudar a los usuarios a reconocer, diagnosticar y recuperarse de los errores

    Los mensajes de error deben expresarse en un lenguaje claro (sin códigos técnicos), indicar con precisión el problema y sugerir de manera constructiva una solución.

  10. Ayuda y documentación

    Aunque es mejor si el sistema se puede usar sin documentación, puede ser necesario proporcionar ayuda. Esta información debe ser fácil de buscar, centrada en las tareas del usuario, listar pasos concretos y no ser demasiado extensa.
